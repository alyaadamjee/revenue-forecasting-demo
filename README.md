# Revenue Forecasting on Databricks

A revenue forecasting pipeline for a services business whose fees are partly a **percentage of each client's media spend
or sales** ("dynamic-rate" contracts). It replaces a spreadsheet process with SQL views, scheduled notebooks and a small
app on Databricks.

> **All data in this repository is fake.** Clients, brands, people, emails, IDs and amounts are generated by
> `scripts/generate_fake_data.pl`. Brand names are invented words, and emails use the reserved `example.com` domain.

## The problem

Revenue was forecast in a large Excel contract database (one row per contracted product, monthly revenue for three years),
kept in sync with Salesforce by hand:

- every week someone exported Salesforce opportunities and looked for won deals and renewals missing from the file;
- dynamic-rate lines need a forecast of the client's spend, so every month a workbook per account team went out by email,
  came back filled in, and was consolidated and pasted back into the file;
- open pipeline was spread by month in a separate budget file.

## What this builds

```
 Salesforce opportunities ─┬─► contract checks ──► "add these products" / "these fields disagree"
 (src_sf_*)                │
                           ├─► weighted pipeline ─────────────────────────────┐
                           │                                                  ▼
                           └─► data checks ─► team workbooks ─► team returns ─► rev_forecast_monthly
 Contract database ──────────────────────────────────────────────────────────┘
 (rev_contract_db*)            ▲ app: schedule sends, recipients, downloads
```

| Step | Objects | What it does |
|---|---|---|
| Load | `src_sf_opportunity`, `src_sf_opportunity_products`, `src_teams`, `rev_contract_db`, `rev_contract_db_monthly` | Salesforce opportunities and products (one row per product × platform × market), account teams, and the contract database with its monthly base amount, active flag and revenue. |
| Contract checks | `rev_sf_pid`, `rev_map_category_scope`, `rev_check_new_pids`, `rev_check_salesforce` | Replaces the weekly manual check. Lists won products and open renewals missing from the contract database, and products whose stage, dates, team or renewal link disagree with Salesforce. |
| Pipeline | `rev_settings`, `rev_pipeline_opps`, `rev_pipeline_monthly` | Open deals: Commit at full value, Best Case only at ≥ 60% probability and weighted by it, Pipeline not forecast. Spread by month from the accounting start. Thresholds are editable in `rev_settings`. |
| Data checks | notebook *Salesforce Data Checks*, `rev_sf_filter_values`, `rev_sf_check_*` | Fails when Salesforce stops being read in full: missing columns, stale data, row drops, new stage / pricing / category values nobody has classified, unknown teams, teams losing rows. Warns on blank or unexpected markets. Every run is logged. |
| Team send | notebook *Team Send*, `rev_send_schedule`, `rev_send_log`, `rev_team_recipients`, `rev_team_workbook_rows` | Builds each team's Excel workbook with one tab per client. Each tab has Salesforce rows and manual rows, yellow input cells, grey months outside the contract, drop-downs and sheet protection. The workbook is prefilled from the team's last return. Runs the data checks first and builds nothing if they fail. Emails through Microsoft Graph when configured. |
| Team returns | notebook *Team Returns*, `rev_team_returns`, `rev_team_forecast`, `rev_team_forecast_pid` | Reads every returned workbook by its headers and keeps the latest cycle per team (10+2 beats 9+3). |
| Forecast | `rev_forecast_monthly` | Contract database revenue, plus the weighted pipeline. Dynamic-rate lines are re-priced from the teams' forecast (base × rate, at least the monthly minimum), starting from the cycle's first forecast month. |
| App | `app/` (Streamlit on Databricks Apps) | Schedule a send (cycle, first forecast month, due date, teams), send now or cancel, download workbooks, and edit recipients. Shows the latest data-check result. |

*Simulate Team Returns* exists for the demo only. It plays the part of the teams: it fills the sent workbooks with a fake
forecast and adds one manual row to each, so the returns step has files to read.

### Problems planted in the fake data

The fake data has problems planted on purpose, so the checks have something to find:

- 6 won products left out of the contract database;
- a contract line whose product ID is not in Salesforce;
- one line each with a different team, end date and stage than Salesforce;
- one won product with a blank market.

## Run it

You need a Databricks workspace with Unity Catalog, a SQL warehouse, serverless jobs and the `databricks` CLI logged in.

```sh
export DATABRICKS_WAREHOUSE_ID=<warehouse id>
S=<catalog>.<schema>                       # everything is created here, e.g. main.revenue_demo

perl scripts/generate_fake_data.pl data    # optional – data/ is already generated (fixed seed, same output)
scripts/run_sql.sh $S sql/00_setup.sql     # schema + volumes
for f in data/*.csv; do databricks fs cp --overwrite $f dbfs:/Volumes/${S/./\/}/inputs/$(basename $f); done
for f in sql/0[1-5]*.sql; do scripts/run_sql.sh $S $f; done
```

Import the notebooks into one workspace folder with these names. Use a plain hyphen, because `dbutils.notebook.run` only
accepts ASCII paths:

| File | Notebook name |
|---|---|
| `notebooks/salesforce_data_checks.py` | `Revenue Demo - Salesforce Data Checks` |
| `notebooks/team_send.py` | `Revenue Demo - Team Send` |
| `notebooks/simulate_team_returns.py` | `Revenue Demo - Simulate Team Returns` |
| `notebooks/team_returns.py` | `Revenue Demo - Team Returns` |

Every notebook has a `schema` widget, which defaults to `main.revenue_demo`. Then:

1. Schedule a send, in the app or with SQL:
   ```sql
   INSERT INTO <schema>.rev_send_schedule VALUES ('demo-0001', '10+2', DATE'2026-11-01', current_timestamp(), DATE'2026-11-16',
     array('NA-North','NA-South','NA-East','NA-West','NA-Central','EU-North','EU-South','Unassigned'),
     NULL, 'scheduled', 'me', current_timestamp(), current_timestamp());
   ```
2. Run *Team Send* with `send_id = demo-0001`. The workbooks are written to `/Volumes/<catalog>/<schema>/revenue_teams/sends/10+2/`.
3. Run *Simulate Team Returns* with `cycle = 10+2`, then run *Team Returns*.
4. Query `rev_forecast_monthly`, `rev_check_new_pids`, `rev_check_salesforce` and `rev_sf_check_latest`.

To see a workbook prefilled from the previous return, schedule and send a later cycle (e.g. `11+1`, first month 2026-12-01).

**App:** deploy `app/` as a Databricks App with a SQL warehouse resource. In `app.yaml`, set `SEND_JOB_ID` to a job that runs
*Team Send* (e.g. hourly) and `REV_SCHEMA` to your schema. Grant the app's service principal:

- `USE CATALOG` and `USE SCHEMA`;
- `SELECT` on the views;
- `SELECT, MODIFY` on `rev_send_schedule` and `rev_team_recipients`;
- `READ VOLUME` on `revenue_teams`.

## Results on the fake data

One end-to-end run gave:

| | |
|---|---|
| Contract database | 278 lines; revenue $28.3M (2025), $28.5M (2026) |
| Contract checks | 6 products to add, 4 field mismatches (product not in Salesforce, stage, end date, team) |
| Pipeline | 52 open deals in the forecast |
| Data checks | passed, with 1 warning (blank market) |
| Team send | 8 workbooks, 78 Salesforce rows, 28 client tabs |
| Team returns | 8 workbooks read, 86 rows (8 of them manual) |
| Forecast | $28.5M (2026) and $29.8M (2027), including team-forecast lines of $3.9M / $5.8M and pipeline of $0.1M / $4.2M |
